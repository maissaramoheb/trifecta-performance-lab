# Dark Tactical Performance Operations System

## Product character

Trifecta Performance Lab is an Arabic-first trainer operations system. It must help an experienced instructor orient, inspect evidence, diagnose performance, and make a defensible progression decision without visual noise. The interface is engineered around operational context, not decoration.

## Visual contract

- Canvas layers: `#070B10`, `#0A1016`, `#0D151D`, `#111C26`, and `#16232E`.
- Borders establish depth: `#21303C` for ordinary separation and `#334756` for active structure.
- Primary text: `#F2F6F8`; supporting text: `#B2C0CA`; metadata: `#7E909D`.
- Tactical teal `#20C7B7` owns interaction and focus. Cyan and steel blue support technical information. Amber is restricted to pending, warning, and controlled emphasis.
- Operational colours are semantic invariants: Go `#35C878`, No-Go `#F0525B`, Need More Data `#5596E6`, Retest `#E1A53A`, Pending `#7D8D99`.
- IBM Plex Sans Arabic is the Arabic-first UI face. Latin content uses IBM Plex Sans/system sans; identifiers use a restrained monospace stack.
- Geometry uses 4–10px radii, thin borders, strong alignment, compact metadata, and selective illuminated edges. Large gradients, glass blur, camouflage, weapon imagery, and decorative scan noise are prohibited.

## Signature model

The Trifecta is represented by an original responsive isometric pyramid. Three visible faces converge on an integrated performance core:

- Physical: teal.
- Technical: cyan/steel blue.
- Cognitive / Neurophysiological: controlled amber/oxide.
- Observable Actual Performance: white core with a restrained teal edge.

External controls identify each face and remain semantic keyboard-operable tabs. The entrance sequence resolves structure, faces, edges, and core in approximately 1.5 seconds. A single slow edge sweep provides ambient energy. Reduced motion renders the settled model immediately and disables ambient movement.

## Information architecture

- The command bar always exposes product identity, route context, saved/offline state, mode, language, and mobile navigation.
- Desktop navigation is grouped and expandable. Mobile uses a full-height drawer; content never inherits desktop sidebar width.
- Pages use an operational header, then the primary task surface, followed by supporting evidence. Status and primary actions remain visible before secondary explanation.
- Builders preserve `Level → Station → Drill → Gate`. Form validity, saved state, and Gate decisions are visually distinct systems.
- Curriculum evidence is shown as `Drill → Evidence → Gate → Progression/Remediation`, never as a compensating total performance score.
- Critical Failure uses a contained red decision frame, explicit language, lock indication, evidence, remediation, retest conditions, and attempt history. The full page never turns red.

## Reference-derived principles

- NASA display guidance: keep essential context persistent, match graphics to the operator’s mental model, and reserve critical colour for off-nominal attention.
- Carbon dark themes: create hierarchy through progressively lighter neutral layers and use action/status colour sparingly.
- Siemens industrial systems: maintain one consistent operational model across complex workspaces and devices.
- Public command-and-control products: present decision points and operator context rather than raw noise.

These are interaction and hierarchy principles only. No proprietary screen, icon, brand, asset, or layout is reproduced.
